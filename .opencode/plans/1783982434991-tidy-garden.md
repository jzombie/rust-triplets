# Plan: Verify & Test Hard Negative Mining Bypass for Explicit Negatives

## Question Answered

**Yes, hard negative mining (BM25 or random) ONLY applies when explicit hard negatives are NOT already defined.**

### Evidence

1. When `negative_columns` is non-empty in HuggingFace config, the source emits a recipe with `NegativeStrategy::SameRecord` (`crates/triplets-hf-source/src/huggingface_source.rs:5237-5251`).

2. When `SameRecord` is used, `select_negative_record` (`crates/triplets-core/src/sampler/mod.rs:1191-1198`) returns the anchor record itself, **completely bypassing** `self.negative_backend.choose_negative()`:
   ```rust
   NegativeStrategy::SameRecord => {
       // Return the anchor record itself. The caller
       // (finalize_triplet_with_negative) will call select_chunk on
       // this record using the recipe's negative_selector, which
       // picks from Context sections.
       Some((Arc::new(anchor_record.clone()), false))
   }
   ```

3. For all other strategies (`WrongArticle`, `WrongPublicationDate`, `QuestionAnswerMismatch`), the backend is always called via `self.negative_backend.choose_negative()`.

4. The backend (`Bm25Backend` or `DefaultBackend`) is **never instantiated or invoked** for `SameRecord` — the match arm returns early.
