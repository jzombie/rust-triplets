# Plan: Eliminate String Cloning Overhead in AoS Pipeline

## Problem

`SplitState::step()` in `crates/triplets-offline-embedder/src/split_state.rs` **clones every string** when moving from `SamplerBatch` to `PendingState`. The `batch` parameter is consumed by value (`batch: SamplerBatch`), so strings can be **moved** — but the current chunking loop borrows `&entries[chunk_start..chunk_end]`, preventing moves.

Additionally, the `accumulate` function (line 134) only handles pairs, with a TODO acknowledging this is confusing. It should be deleted — `step()` already handles both pairs and triplets directly.

## Cloning Hotspots to Eliminate

| Line | Current (clone) | Target (move) |
|---|---|---|
| 269 | `entry.anchor_text.clone()` | `entry.anchor_text` |
| 271 | `entry.candidate_text.clone()` | `entry.candidate_text` |
| 333 | `chunk[i].anchor_text.clone()` | `entry.anchor_text` |
| 335 | `chunk[i].pos_text.clone()` | `entry.pos_text` |
| 337 | `chunk[i].neg_text.clone()` | `entry.neg_text` |

**Cannot eliminate:** Embedding vector clones (`embedded[map[i]].clone()`) — dedup reuses vectors across entries, requiring clones. This is parity with any implementation.

## Refactoring: Two-Phase Execution Model

The key insight: separate the **borrow phase** (embedding, which needs `&str` references) from the **consume phase** (assembly, which moves `String` values).

### Step 1: Pair Path — Two-Phase Execution

**File:** `crates/triplets-offline-embedder/src/split_state.rs` (lines 199–279)

```rust
SamplerBatch::Pairs(entries) => {
    let mut all_anchor_vecs = Vec::with_capacity(entries.len());
    let mut all_candidate_vecs: Vec<Option<Vec<f32>>> = Vec::with_capacity(entries.len());

    // Phase 1: Borrow and Embed (entries untouched)
    for chunk in entries.chunks(chunk_size) {
        let anchor_refs: Vec<&str> = chunk.iter().map(|e| e.anchor_text.as_str()).collect();
        let anchor_vecs = match embedder.embed(&anchor_refs) { /* ... */ };
        // ... validation, dedup, candidate embedding ...
        all_anchor_vecs.extend(anchor_vecs);
        // Store candidate vecs (None = reuse anchor)
        for (i, entry) in chunk.iter().enumerate() {
            if entry.candidate_text == entry.anchor_text {
                all_candidate_vecs.push(None);
            } else {
                all_candidate_vecs.push(Some(candidate_embs[candidate_indices[i]].clone()));
            }
        }
    }

    // Phase 2: Consume and Assemble (zero-copy string moves)
    for (entry, (a_vec, c_vec)) in entries.into_iter()
        .zip(all_anchor_vecs.into_iter().zip(all_candidate_vecs.into_iter()))
    {
        self.pending.push_pair(PendingPair {
            anchor_text: entry.anchor_text,       // MOVED
            anchor_vec: a_vec,                     // MOVED
            candidate_text: entry.candidate_text,  // MOVED
            candidate_vec: c_vec.unwrap_or_else(|| a_vec_ref.clone()),
            label: entry.label,
        });
    }
}
```

**Note on candidate_vec reuse:** When `candidate_text == anchor_text`, the candidate vector should equal the anchor vector. In the consume phase, we've already moved `a_vec`, so we need to clone it for the candidate field. This is unavoidable when the same vector serves two fields — but it replaces the previous clone-of-a-clone pattern.

### Step 2: Triplet Path — Two-Phase Execution

**File:** `crates/triplets-offline-embedder/src/split_state.rs` (lines 281–345)

Same structural separation. Accumulate `all_anchor_vecs`, `all_pos_vecs`, `all_neg_vecs` during the borrowed `chunks(chunk_size)` loop. Consume `entries.into_iter()` only after all embedding completes, zipping with the accumulated vectors.

Add convenience methods to `PendingState` for cleaner test code and potential future use:

```rust
impl PendingState {
    pub fn push_pair(&mut self, entry: PendingPair) {
        if let PendingState::Pairs(v) = self { v.push(entry); }
    }
    pub fn push_triplet(&mut self, entry: PendingTriplet) {
        if let PendingState::Triplets(v) = self { v.push(entry); }
    }
}
```
