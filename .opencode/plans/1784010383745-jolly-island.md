# Plan: Eliminate String Cloning Overhead in AoS Pipeline

## Problem

The `SplitState::step()` function in `crates/triplets-offline-embedder/src/split_state.rs` **clones every string** when moving from `SamplerBatch` to `PendingState`. The `batch` parameter is already consumed by value (`batch: SamplerBatch`), so the strings inside `PairEntry`/`TripletEntry` can be **moved** instead of cloned, achieving zero-copy text transfers.

## Current Cloning Hotspots

| Location | What is cloned | Can be eliminated? |
|---|---|---|
| `split_state.rs:269` | `entry.anchor_text.clone()` | **YES** — use `into_iter()` |
| `split_state.rs:271` | `entry.candidate_text.clone()` | **YES** — use `into_iter()` |
| `split_state.rs:333` | `chunk[i].anchor_text.clone()` | **YES** — restructure to owned iterator |
| `split_state.rs:335` | `chunk[i].pos_text.clone()` | **YES** — restructure to owned iterator |
| `split_state.rs:337` | `chunk[i].neg_text.clone()` | **YES** — restructure to owned iterator |
| `split_state.rs:334,336,338` | `embedded[map[i]].clone()` | **NO** — dedup requires cloning vectors |

## Refactoring Steps

### Step 1: Pair Path — Use `into_iter()` on the entries Vec

**File:** `crates/triplets-offline-embedder/src/split_state.rs`  
**Lines:** 199–279

Change the pair branch from iterating `&entries[chunk_start..chunk_end]` (borrowed) to consuming `entries` via `into_iter()` and skipping/advancing to the chunk range. This allows moving `anchor_text` and `candidate_text` directly.

**Key change:**
```rust
// BEFORE (clones strings):
let chunk = &entries[chunk_start..chunk_end];
// ... later ...
anchor_text: entry.anchor_text.clone(),
candidate_text: entry.candidate_text.clone(),

// AFTER (moves strings):
// Consume entries by value, skip to chunk_start
let chunk_iter = entries.into_iter().skip(chunk_start).take(chunk_size);
// ... later ...
anchor_text: entry.anchor_text,  // MOVED (zero-copy)
candidate_text: entry.candidate_text,  // MOVED (zero-copy)
```

**Caveat:** The current chunking loop iterates multiple chunks from the same `entries` Vec. With `into_iter()`, we need to consume the entire Vec in one pass, chunking internally. Restructure the loop to consume all entries at once and chunk the iterator.

### Step 2: Triplet Path — Restructure to Owned Iterator

**File:** `crates/triplets-offline-embedder/src/split_state.rs`  
**Lines:** 281–345

The triplet path currently takes `chunk = &entries[chunk_start..chunk_end]` (borrowed slice), which prevents moving strings. Restructure to consume `entries` via `into_iter()` and chunk the owned iterator.

**Key change:**
```rust
// BEFORE (borrows chunk, clones strings):
let chunk = &entries[chunk_start..chunk_end];
// ...
anchor_text: chunk[i].anchor_text.clone(),

// AFTER (owns iterator, moves strings):
// Collect all entries into chunks of owned data
let mut remaining = entries.into_iter();
loop {
    let chunk: Vec<TripletEntry> = remaining.by_ref().take(chunk_size).collect();
    if chunk.is_empty() { break; }
    // ... embed unique texts ...
    for entry in chunk {
        anchor_text: entry.anchor_text,  // MOVED
        pos_text: entry.pos_text,        // MOVED
        neg_text: entry.neg_text,        // MOVED
    }
}
```

### Step 3: Update Accumulate Function (Low Priority)

**File:** `crates/triplets-offline-embedder/src/split_state.rs`  
**Lines:** 134–160

The `accumulate` function takes `anchor_texts: &[String]` and clones them. Since it's a lower-level API and not in the hot path (only used for pairs, and `step()` handles triplets directly), this is lower priority. Could be optimized later by accepting `Vec<String>` and using `into_iter()`.

## What CANNOT Be Eliminated

- **Embedding vector clones** (`embedded[map[i]].clone()`): The deduplication logic reuses vectors across multiple entries. When `anchor_text == pos_text`, the same embedding vector is used for both fields, requiring a clone. This is **identical overhead** to any SoA implementation — not an AoS regression.
